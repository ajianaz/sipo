## 1. Product Vision

> "UMKM kecil butuh catat jual-beli tanpa kompleksitas POS full."

Sipo adalah aplikasi catat pembelian & penjualan offline-first untuk UMKM kecil. Zero setup, zero login, langsung pakai. Fokus ke kecepatan input dan kejelasan laporan — bukan fitur bloat.

### Tagline

**"Catat pembelian & penjualan dalam 3 langkah."**

## 2. Target Users

| Persona | Deskripsi | Pain Point |
|---------|-----------|------------|
| **Pak Budi (Warung Kelontong)** | Pemilik warung, jual beras, minyak, gula | Nggak tahu stok berapa, rugi/laba per barang nggak jelas |
| **Bu Sari (Toko Kecil)** | Pemilik toko kelontong, beli dari supplier | Susah tracking supplier mana, barang apa, berapa banyak |
| **Mas Andi (Pedagang)** | Jualan berbagai barang, catat manual | Buku catat hilang, rekap manual capek |

### User Characteristics

- **Tech-savvy:** Rendah-sedang. Familiar dengan HP Android, bukan power user.
- **Device:** Android mid-range (75%+ market Indonesia).
- **Context:** Sibuk melayani pelanggan, input harus cepat.
- **Connectivity:** Kadang offline, data harus lokal dulu.
- **Age:** 25-55 tahun — UI harus jelas, font cukup besar, tap target besar.

## 3. Core Features (v0.1.0)

### 3.1 Master Satuan

**User Story:** Sebagai pemilik toko, saya ingin mengelola daftar satuan (kg, liter, pcs, dus) agar setiap barang punya satuan yang konsisten.

| Field | Tipe | Required | Notes |
|-------|------|----------|-------|
| nama | text | ✅ | Unique. Contoh: "kg", "liter", "pcs", "dus" |
| deskripsi | text | ❌ | Optional. Contoh: "Kilogram" |
| is_active | boolean | ✅ | Default true. Soft delete |

**Rules:**
- Satuan yang sudah dipakai di Barang TIDAK bisa di-hard delete, hanya soft delete (is_active = false).
- CRUD lengkap.
- List: filter active only di form pemilihan, show all di management page.

### 3.2 Master Barang

**User Story:** Sebagai pemilik toko, saya ingin mengelola daftar barang dengan harga beli dan harga jual agar transaksi otomatis mengambil harga yang benar.

| Field | Tipe | Required | Notes |
|-------|------|----------|-------|
| nama | text | ✅ | Contoh: "Beras Premium 5kg" |
| satuan_id | FK → satuan | ✅ | Pilih dari master satuan |
| harga_beli | decimal | ✅ | Harga beli per satuan |
| harga_jual | decimal | ✅ | Harga jual per satuan |

**Rules:**
- Harga jual boleh sama dengan atau lebih dari harga beli (no validation enforcement).
- Decimal: 2 digit precision.
- Search by nama (fuzzy/contains).

### 3.3 Customer

**User Story:** Sebagai pemilik toko, saya ingin mencatat data supplier/pelanggan agar tahu dari siapa beli dan ke siapa jual.

| Field | Tipe | Required | Notes |
|-------|------|----------|-------|
| nama | text | ✅ | Nama supplier/pelanggan |
| no_hp | text | ❌ | Nomor HP |
| alamat | text | ❌ | Alamat |
| catatan | text | ❌ | Catatan tambahan |

**Rules:**
- CRUD lengkap.
- Pembelian: customer **WAJIB** (ini supplier).
- Penjualan: customer **OPSIONAL** (walk-in bisa tanpa customer).

### 3.4 Transaksi Pembelian

**User Story:** Sebagai pemilik toko, saya ingin mencatat pembelian barang dari supplier (nama barang, jumlah, harga) agar tahu berapa stok yang masuk dan berapa modal yang keluar.

**Flow:**

```
1. Pilih Customer (wajib) — search + recent
2. Tambah item:
   a. Pilih Barang (search + chips)
   b. Isi jumlah (stepper + text field, support decimal)
   c. Harga satuan auto-fill dari harga_beli barang
   d. Subtotal = jumlah × harga_satuan
3. Review: list item + total
4. Simpan → success feedback
```

**Rules:**
- Tipe transaksi: `pembelian`.
- Customer wajib.
- Harga_satuan default dari `barang.harga_beli`, bisa di-edit manual.
- Jumlah: decimal, min 0.01.
- Bisa tambah multiple item.
- Bisa hapus item sebelum simpan.
- Total = sum semua subtotal.

### 3.5 Transaksi Penjualan

**User Story:** Sebagai pemilik toko, saya ingin mencatat penjualan barang ke pelanggan (nama barang, jumlah, harga) agar tahu berapa stok yang keluar dan berapa pendapatan.

**Flow:**

```
1. Pilih Customer (opsional) — search + recent, skip if walk-in
2. Tambah item:
   a. Pilih Barang (search + chips)
   b. Isi jumlah (stepper + text field, support decimal)
   c. Harga satuan auto-fill dari harga_jual barang
   d. Subtotal = jumlah × harga_satuan
3. Review: list item + total
4. Simpan → success feedback
```

**Rules:**
- Tipe transaksi: `penjualan`.
- Customer opsional (walk-in = null).
- Harga_satuan default dari `barang.harga_jual`, bisa di-edit manual.
- Sama seperti pembelian untuk item addition/removal.

### 3.6 Analitik / Laporan

**User Story:** Sebagai pemilik toko, saya ingin melihat rekap pembelian dan penjualan per barang dalam rentang tanggal agar tahu mana barang yang laku dan berapa nilai transaksinya.

**Filter:**

| Filter | Opsi |
|--------|------|
| Periode | Hari Ini, 7 Hari, 30 Hari, Custom Range |
| Barang | Semua Barang, atau pilih 1 barang |

**Output per barang:**

| Metrik | Pembelian | Penjualan |
|--------|-----------|-----------|
| Total qty (dalam satuan) | ✅ | ✅ |
| Total nilai (Rp) | ✅ | ✅ |
| Netto (penjualan qty − pembelian qty) | — | ✅ |

**Views:**
- **Summary all barang**: tabel list — barang, total beli, total jual, netto qty.
- **Detail 1 barang**: breakdown per transaksi, chart sederhana (opsional v0.2).

## 4. Non-Functional Requirements (NFRs)

| NFR | Requirement |
|-----|-------------|
| **Offline-first** | 100% data lokal (SQLite). Tidak perlu internet. |
| **Performance** | Load < 500ms untuk list < 1000 item. Transaksi simpan < 200ms. |
| **Storage** | SQLite file < 50MB untuk 10,000 transaksi. |
| **Platform** | Android first (v0.1). iOS later (v0.3+). |
| **Min SDK** | Android API 24 (Android 7.0). |
| **Language** | Bahasa Indonesia (UI). |
| **Accessibility** | Min font 14sp, tap target 44×44dp. |
| **No auth** | v0.1 = no login, no cloud sync. Device-bound. |

## 8. UX Principles Applied

Principles dari mobile-ux-psychology yang diterapkan:

| # | Principle | Where |
|---|-----------|-------|
| #19 | Bottom nav 3-5 tabs | 4 tabs: Beranda, Barang, Transaksi (center CTA), Laporan |
| #20 | CTA button in center | Transaksi tab elevated, prominent |
| #24 | Active state 2+ visual changes | Filled icon + brand color + bold text |
| #25 | Nav separation | Subtle shadow above bottom nav |
| #32 | Empty states as engagement | Setiap list kosong: ilustrasi + CTA |
| #33 | Selection over input | Pilih barang = chips + search, bukan free-text |
| #34 | Input method = frequency | Jumlah: stepper + text field (frequent input) |
| #36 | Recognition over recall | Recent customers, recent barang |
| #37 | Preview before commit | Review total sebelum simpan transaksi |
| #38 | System feedback | Animasi checkmark saat transaksi tersimpan |
